# Frontend → admin → MongoDB audit (14 October 2026)

Business content extends the existing `pages`, content collections and Academy configuration. IDs and records are retained; there is no seeding or automatic publication. Site content editors are linked from `/admin/pages`; they load the existing singleton by slug, or open an unsaved draft. Navigation, access rules, technical configuration, interface labels and academic-integrity rules remain in code.

## Fixed evidenced gaps

- Added missing singleton editors and published-data integration for About, contact/company/social details, Academy banners and listing introductions, using the existing page-content system and role grants.
- Added editable solution pathways; sparse/empty scope blocks no longer crash a solution page or display undefined indexed items.
- Preserved team portraits through public decoding and display. Published mentor cards use their supplied photos.
- Connected saved Academy marketing metadata, images/galleries and curriculum outlines to public course listings and homepage previews. Projections never include restricted lesson text, private file keys or resource paths. Paid amounts remain server-calculated by the existing pricing APIs; a browser assertion confirmed the homepage uses the saved 50000-minor-unit course price. The Academy landing page now loads up to 100 published previews instead of silently limiting its local search to three, with the existing full course directory available for pagination.
- Added the existing explicit public marketing-preview field to the course editor and public content metadata. Lesson embed URLs remain exclusively in the permission-checked lesson APIs, including public introductory lessons.
- Project popup galleries use saved normalized videos. Publication popups use supplied abstracts and citations.
- New section rows default to visible, matching the storage schema; approval checkboxes retain their false default. Process steps respect section visibility.
- Added permission-checked uploaded-media previews to editors and draft previews; asset validation errors remain visible.
- Product API failures are distinguished from empty published catalogs. Demo fallback remains explicitly illustrative.
- Saved homepage/listing SEO is consumed. Public requests use `no-store`; request-local deduplication does not retain stale content across requests. The client loader's bounded cache-expiry/missing/error behavior is tested.

## Verification and limits

Frontend/backend lint, typecheck and builds were run. `editorial-cms.integration.test.mjs` now exercises draft → save/reload → publish/public display → edit/public update → restart/reload same IDs/revisions → archive for every content collection and the new singleton groups. Browser verification used a separate temporary backend/database, actual admin sign-in and temporary re-encoded media; seven content types completed the actual UI lifecycle. No real published records were edited. Media transport was local test transport; iframe hosts were isolated fixtures.

Integration coverage: editorial CMS permissions/transactions/restart, media validation/upload failure, Academy management, protected lessons/resources, scholarships, commerce and cart concurrency. Legacy Step 6/8/10 suites require their exact fixture backends; their guarded workflows were NOT RUN in the normal application environment. Enabled email delivery was never used; no real charges or production code redemption occurred.

Remaining code-owned defaults include business copy used as pre-publication fallbacks, category/navigation taxonomies and clearly labelled fictional profiles, learner personas, illustrative kits/courses/projects/research/publications. Published overrides replace the corresponding business data. Generic instructions, validation/availability notices and academic-integrity rules remain in code. No demo was copied into MongoDB automatically.

NOT RUN: real R2 delivery/provider outage recovery, external YouTube/Vimeo playback, real payment provider/sandbox, production private-video hosting, production notification delivery, production data writes and deployment. These require separately supplied infrastructure; sealed internal payment fixtures do not establish provider connectivity.

The first expanded integration run failed when the pre-existing development MongoDB hit its open-file limit and restarted. Final self-contained verification uses a separate temporary MongoDB replica set with `nofile=65536`; the normal database configuration was not changed. A public-summary lesson-embed regression was caught by the Academy management suite and corrected without weakening its assertion.

Final results: frontend/backend lint, typecheck and build PASS; 19 backend validation/unit checks PASS; five frontend decoder/cache/demo tests PASS. All five self-contained content/Academy integration suites passed on the dedicated replica set (the affected CMS/management pair was rerun after correcting the summary contract). Real browser checks completed seven content lifecycles, 14 public route renders, media preview/error handling, Academy resource persistence, process-step persistence, saved pricing and mobile navigation. The owned browser database/media, fixture account state and dedicated test container/volumes were removed. The normal application still returned readiness `ok` and homepage HTTP 200. No deployment was performed.
